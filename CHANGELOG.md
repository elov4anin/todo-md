# Changelog

## [1.2.0] — 2026-08-30

### Added
- Стандартный заголовок dashboard теперь содержит имя каталога проекта — `Задачи — <имя-каталога-проекта>` — одновременно во вкладке браузера (`<title>`) и видимом заголовке (`<h1>`)
- 3 интеграционных теста на одинаковый заголовок при чтении директории, JSONL-файла и stdin, HTML-экранирование имени каталога и полное переопределение через `--title` (всего 91)

### Changed
- Опция `todo-md dashboard --title="..."` остаётся полным явным переопределением и не получает автоматический суффикс с именем проекта; пример команды добавлен в README и справку CLI

## [1.1.0] — 2026-08-29

### Added
- Поддержка каталогов эпиков: `create EPIC-x` создаёт `todo/EPIC-x/EPIC-x.todo.md`, а `create TASK-y --epic=EPIC-x` — `todo/EPIC-x/TASK-y.todo.md`; в зонах backlog/done/cancelled каталог эпика сохраняется (`todo/<zone>/EPIC-x/<ID>.todo.md`); самостоятельные задачи остаются плоскими — `todo/<zone>/TASK-y.todo.md`
- `set TASK-y epic=EPIC-x` и очистка `epic=` атомарно переносят задачу в каталог эпика (или из него) с исправлением относительных Markdown-ссылок; при ошибке изменения полностью откатываются
- Dashboard при прямом чтении директории строит кликабельные `file://`-ссылки на карточки задач и заголовки эпиков без `--base`, включая вложенные пути `todo/<zone>/EPIC-x/…`; для JSONL-файла и stdin ссылки по-прежнему требуют явного `--base`, абсолютные значения `file` связываются как есть
- 21 новый интеграционный тест на layout эпиков, переходы, `set epic`, валидацию, экспорт и dashboard (всего 88)

### Changed
- Переходы `start`, `review`, `backlog`, `done`, `cancel` и `set status=…` сохраняют каталог эпика: `todo/EPIC-x/TASK-y.todo.md` переносится, например, в `todo/done/EPIC-x/TASK-y.todo.md`; переход самого эпика перемещает только файл эпика
- Изменяющая команда нормализует старый плоский файл задачи с заполненным полем `epic` — переносит его в канонический каталог эпика соответствующей зоны; команды чтения по-прежнему находят плоские файлы, а `validate` сообщает о них предупреждением, а не ошибкой
- `validate` дополнительно проверяет соответствие каталога `EPIC-*` ID эпика и полю `epic` задачи
- `export-jsonl` выдаёт в поле `file` фактический вложенный путь, в `folder` — зону статуса
- **Миграция для скриптов:** если автоматизация ожидает плоские пути `todo/<ID>.todo.md` у задач с эпиком, после обновления фактический путь — `todo/<zone>/EPIC-x/<ID>.todo.md`. Точный путь каждой задачи доступен в поле `file` вывода `npx todo-md export-jsonl todo/` или рекурсивным поиском (`find todo -name '<ID>.todo.md'`). Обязательная миграция не требуется: старые плоские файлы читаются всеми командами и нормализуются при первом изменении.

### Fixed
- CLI больше не противоречит документации: ранее `create` размещал эпики и задачи с `--epic` плоскими файлами, хотя поставляемое руководство требовало каталоги `EPIC-*`
- Ссылки dashboard корректно кодируют пробелы, кавычки и не-ASCII сегменты пути

### Security
- Dashboard игнорирует поле `url` из входного JSONL и всегда строит файловую ссылку заново из `file`; HTML-атрибуты экранируются полностью, включая кавычки — произвольный входной `url` не попадает в `href`

## [1.0.0] — 2026-08-24

### Changed
- Полный порт CLI с PHP 8.4 на TypeScript и Node.js 24 LTS
- Установка выполняется как Git dependency через npm; готовый `dist/` хранится в Git и не собирается в проекте-потребителе
- Конфигурация проекта переведена с исполняемого `.todo-md.php` на безопасный `.todo-md.json`
- Все команды и примеры документации переведены на `npx todo-md`

### Added
- 67 тестов на `node:test`: CLI, parser, validator, переходы, rollback, ссылки, init, JSONL и dashboard
- Кроссплатформенный CI для Linux, macOS и Windows
- JSON Schema для `.todo-md.json`
- Полностью автономный HTML dashboard со встроенным Chart.js
- Проверка установки собранного пакета без lifecycle-скриптов

### Removed
- PHP-исходники, Composer package, Makefile и PHP test runner

## [0.0.12] — 2026-08-22

### Changed
- Модель завершения задачи: `review` — проверка результата до передачи на приёмку (CI, self-review, доработки); `done` — результат передан на приёмку; при замечаниях приёмки задача возвращается из `done` в `review`
- Механика git-порядка (push, апрув, branch protection) убрана из документации формата задач — момент перевода в `done` определяет процесс проекта (например, пакет `elov4anin/git-workflow`)
- `review --> done: Выполнена` в диаграмме переходов; п.5 «Завершение» — одно действие, «возврат из done» — в разделе CLI-команд

### Added
- Front matter `package: elov4anin/todo-md` в распределяемые документы (кроме шаблонов) — атрибуция источника в проектах-потребителях

## [0.0.11] — 2026-08-20

### Fixed
- Точечный `validate <файл>` резолвит `depends_on`/`epic` по всему дереву задач проекта (включая `done/`, `cancelled/`, `backlog/`) — без ложных ошибок «references unknown ID»; валидируются по-прежнему только переданные файлы
- `set <ID> f1=v1 f2=v2 ...` применяет все присваивания одной атомарной записью (все или ничего, с rollback); аргумент без `=` и комбинация `status` с другими полями — явная ошибка вместо молчаливого игнорирования
