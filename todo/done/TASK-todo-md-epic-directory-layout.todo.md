# TASK-todo-md-epic-directory-layout: Согласовать CLI со структурой каталогов эпиков

## 0. Простое описание (Human Brief)

### Проблема простыми словами (Problem)
- Руководство требует хранить эпик в собственном каталоге `EPIC-*`, а связанную задачу — рядом с ним в каталоге этого эпика внутри соответствующей зоны доски.
- `npx todo-md create` сейчас всегда создаёт плоские пути вида `todo/TASK-*.todo.md` и `todo/EPIC-*.todo.md`, даже когда передан `--epic`.
- Команды смены статуса строят целевой путь только из зоны доски и имени файла, поэтому вложенная задача после `start`, `review`, `backlog`, `done` или `cancel` теряет каталог эпика.
- CLI противоречит собственной документации, а пользователь не может полагаться на единую структуру файлов при создании и ведении эпиков.

### Варианты или путь решения (Solution Sketch)
- Ввести одну функцию вычисления канонического пути элемента по статусу, виду элемента и полю `epic`.
- Использовать её в создании, переходах и изменении поля `epic`; рекурсивный поиск оставить общей основой для чтения.
- Старые плоские файлы продолжать находить, а при первой изменяющей команде переносить в канонический путь с безопасным переписыванием ссылок.

### Ожидаемый результат (Expected Result)
- Эпики и входящие в них задачи автоматически сохраняют документированную структуру каталогов во всех состояниях доски.
- Все CLI-команды одинаково видят вложенные файлы, не ломают локальные Markdown-ссылки и не требуют ручного перемещения.
- Существующие доски с плоскими файлами продолжают читаться и могут быть постепенно нормализованы без отдельной обязательной миграции.

## 1. Концепция и Цель (Concept and Goal)

### История (User Story)
> **User Story:** Как пользователь `todo-md`, я хочу, чтобы CLI сам размещал эпики и связанные задачи в каталогах `EPIC-*` и сохранял эту структуру при смене статуса, чтобы файловая доска соответствовала руководству и оставалась предсказуемой.

### Цель по SMART (Goal)
- За одну задачу согласовать `create`, переходы, `set`, `validate`, экспорт и dashboard с единым контрактом путей эпиков; подтвердить сценарии интеграционными тестами и успешным `npm run check`.

## 2. Контекст и Границы (Context and Scope)

- **Где делаем:** `src/board.ts`, `src/parser.ts`, `src/validator.ts`, `src/cli.ts`, тестовые helpers и интеграционные тесты в `tests/`; синхронно обновить `dist/` и пользовательскую документацию CLI.
- **Текущее поведение:** `create()` формирует `todo/<zone>/<ID>.todo.md`; `transition()` переносит в `todo/<zone>/<basename>`; `set epic=...` меняет только front matter. Рекурсивные `findTodoFiles()` и `findFileById()` уже находят вложенные файлы.
- **Канонический контракт:**
  - активный эпик: `todo/EPIC-x/EPIC-x.todo.md`;
  - активная задача эпика: `todo/EPIC-x/TASK-y.todo.md`;
  - backlog: `todo/backlog/EPIC-x/<ID>.todo.md`;
  - done: `todo/done/EPIC-x/<ID>.todo.md`;
  - cancelled: `todo/cancelled/EPIC-x/<ID>.todo.md`;
  - самостоятельная задача остаётся плоской: `todo/<zone>/TASK-y.todo.md`.
- **Правило группировки:** эпик использует каталог собственного ID; задача использует каталог из `epic`; статус каждого файла независим, поэтому переход эпика не переносит его дочерние задачи целиком.
- **Обратная совместимость:** плоские эпики и плоские задачи с заполненным `epic` должны оставаться доступными для чтения и операций; изменяющая команда нормализует только затронутый файл.
- **Границы (Out of Scope):** массовая миграция существующих досок, новая команда миграции, изменение YAML-схемы, новый статус, перемещение всех элементов эпика одной командой, рефакторинг dashboard вне поддержки вложенных путей.

## 7. Риски и зависимости (Risks and Dependencies)
- **Риск обратной совместимости:** немедленная ошибка для старого плоского layout сломает CI потребителей; поэтому чтение сохраняется, а нормализация выполняется постепенно.
- **Риск потери ссылок:** дополнительный уровень вложенности меняет относительные пути; сценарии inbound/outbound и rollback обязательны.
- **Риск выхода за рабочий каталог:** путь строится из front matter; до `resolve()` нужно проверить ID и гарантировать нахождение результата внутри `todo/`.
- **Зависимости:** отсутствуют; рекурсивный обход и транзакция уже реализованы в `src/parser.ts` и `src/transaction.ts`.
