# TASK-todo-md-dashboard-epic-paths: Поддержать вложенные пути эпиков в dashboard

## 0. Простое описание (Human Brief)

### Проблема простыми словами (Problem)
- После перехода на каталоги `EPIC-*` значения `file` в JSONL станут вложенными: `todo/EPIC-x/TASK-y.todo.md`, `todo/done/EPIC-x/TASK-y.todo.md` и аналогично для файла эпика.
- Рекурсивный экспорт уже сохраняет такие пути, а dashboard связывает задачи с эпиком по front matter, поэтому основная группировка не зависит от глубины каталога.
- Однако `renderDashboard()` превращает относительный `record.file` в кликабельный `file://` URL только при переданном `--base`. Даже прямой запуск `todo-md dashboard todo/`, где CLI знает рабочий корень, оставляет карточки задач и заголовки эпиков без ссылок.
- Тесты dashboard проверяют только наличие ID и Chart.js; они не защищают вложенные пути, ссылки на файлы, раздельные статусы эпика и его задач и безопасную обработку URL из JSONL.

### Варианты или путь решения (Solution Sketch)
- Для прямого чтения директории передавать в renderer известную базу автоматически; для JSONL-файла и stdin сохранить явный `--base`, потому что происхождение относительных путей нельзя надёжно угадать.
- Оставить связь task → epic по полю `epic`, а физический путь использовать только как адрес исходного файла.
- Добавить интеграционные тесты на вложенные записи и безопасное формирование ссылок, не меняя существующую визуальную модель dashboard.

### Ожидаемый результат (Expected Result)
- Dashboard, построенный прямо из доски, показывает задачи эпиков независимо от их статуса и открывает фактические вложенные файлы без обязательного `--base`.
- Dashboard из JSONL предсказуемо формирует те же ссылки при явном `--base` и не принимает произвольный входной `url` как готовый HTML-атрибут.
- Реализация каталогов эпиков не вызывает скрытых регрессий в канбане, группировке по эпикам, графиках и диаграмме Ганта.

## 1. Концепция и Цель (Concept and Goal)

### История (User Story)
> **User Story:** Как пользователь HTML-dashboard, я хочу открывать вложенные файлы задач и эпиков из карточек и видеть правильную группировку после смены их статусов, чтобы навигация по доске оставалась рабочей после внедрения каталогов `EPIC-*`.

### Цель по SMART (Goal)
- После завершения `TASK-todo-md-epic-directory-layout` адаптировать формирование файловых URL и добавить контрактные тесты dashboard для канонических вложенных путей; подтвердить результат успешным `npm run check`.

## 2. Контекст и Границы (Context and Scope)

- **Где делаем:** `src/dashboard.ts`, ветка `commandDashboard()` в `src/cli.ts`, `assets/dashboard-template.html`, `tests/init-dashboard.test.ts`; при необходимости fixtures/helpers в `tests/support.ts`, справка CLI и раздел dashboard в `README.md`.
- **Поток данных:** `findTodoFiles()` рекурсивно находит файлы → `extractRecord()` записывает фактический относительный `file`, `folder`, `status`, `epic` → `renderDashboard()` добавляет производный `url` → шаблон связывает карточки и заголовки эпиков по `id`/`epic`.
- **Уже работает:** рекурсивный обход, определение зоны по `done/backlog/cancelled`, группировка и графики по `record.epic`; они требуют регрессионного покрытия, но не нового алгоритма по физическому каталогу.
- **Текущий дефект ссылок:** в directory-mode `extractRecord(file, io.cwd())` возвращает относительный путь, но `renderDashboard(..., base=undefined)` не создаёт `url`, хотя `io.cwd()` известен.
- **Правило базы:** directory-mode по умолчанию использует корень, относительно которого сформирован `record.file`; явный `--base` имеет приоритет. JSONL-файл и stdin получают ссылки только с явным `--base`, абсолютный `record.file` остаётся поддержан.
- **Границы (Out of Scope):** изменение структуры JSONL, редизайн dashboard, новая визуальная иерархия каталогов, парсинг содержимого `.todo.md` в браузере, изменение расчётов метрик и перенос логики канонических путей из родительской задачи.

## 7. Риски и зависимости (Risks and Dependencies)
- **Зависимость:** `TASK-todo-md-epic-directory-layout` должна сначала определить и реализовать окончательные канонические пути.
- **Риск неверной базы:** JSONL может быть создан в другом рабочем каталоге; поэтому автоматическая база допустима только для непосредственного обхода директории.
- **Риск XSS/HTML injection:** JSONL считается внешним вводом; `url` и строковые поля нельзя доверять при сборке `innerHTML`.
- **Риск ложной связи:** одинаковый каталог не заменяет поле `epic`; dashboard должен сохранить семантическую связь по ID.
