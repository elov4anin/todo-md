# TASK-todo-md-dashboard-repository-name: Добавить имя каталога репозитория в заголовок dashboard

## 0. Простое описание (Human Brief)

### Проблема простыми словами (Problem)
- Несколько проектов создают одинаково выглядящие файлы `dashboard.html` с заголовком «Задачи».
- После открытия файла нельзя сразу понять, к какому репозиторию относится дашборд; это особенно мешает при одновременной работе с несколькими проектами.

### Варианты или путь решения (Solution Sketch)
- При формировании стандартного заголовка определить имя каталога проекта и добавить его к слову «Задачи».
- Использовать одно итоговое значение и для HTML `<title>`, и для видимого `<h1>`; существующий `--title` сохранить как явное переопределение заголовка.

### Ожидаемый результат (Expected Result)
- По вкладке браузера и заголовку страницы сразу видно, задачи какого проекта показывает открытый дашборд.

## 1. Концепция и Цель (Concept and Goal)

### История (User Story)
> **User Story:** Как пользователь нескольких todo-md-досок, я хочу видеть имя каталога проекта в заголовке дашборда, чтобы не путать открытые дашборды разных репозиториев.

### Цель по SMART (Goal)
- В текущей итерации изменить стандартный заголовок, создаваемый командой `todo-md dashboard`, на формат `Задачи — <имя-каталога-проекта>`, синхронно вывести его в `<title>` и `<h1>`, сохранить контракт `--title` и подтвердить поведение автоматическими тестами и `npm run check`.

## 2. Контекст и Границы (Context and Scope)

- **Где делаем:** `src/cli.ts` и/или `src/dashboard.ts`, `assets/dashboard-template.html`, тесты dashboard в `tests/init-dashboard.test.ts`; при необходимости справка `dashboard --help` и раздел dashboard в `README.md`.
- **Текущее поведение:** `commandDashboard()` передаёт в `renderDashboard()` строку `Задачи`, если пользователь не указал `--title`; шаблон подставляет её одновременно в `<title>` и `<h1>`.
- **Источник имени проекта:** имя каталога корня проекта, в котором выполняется команда; для обычного запуска из корня репозитория это `basename` текущего рабочего каталога. Решение не должно читать Git-конфигурацию и не должно зависеть от наличия `.git`.
- **Явное переопределение:** значение `--title` остаётся полным пользовательским заголовком и не дополняется автоматически именем каталога.
- **Границы (Out of Scope):** изменение формата JSONL и `ExportRecord`, редизайн dashboard, добавление метаданных репозитория в карточки задач, определение имени по remote URL или `package.json`.

## 7. Риски и зависимости (Risks and Dependencies)
- **Риск неверного источника имени:** входной JSONL может находиться вне репозитория, поэтому имя проекта нельзя выводить из пути входного или выходного файла; источником остаётся корень запуска CLI.
- **Риск регрессии `--title`:** автоматическое добавление имени не должно менять явно заданный пользователем заголовок.
- **Зависимости:** внешних и межзадачных зависимостей нет.
